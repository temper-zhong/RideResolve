# CR-001 阶段性结果与路线变更论证

> 状态：本地探针工程完成，云端 Gate A 闭环尚未执行  
> 结论强度：足以支持继续进行受控云端探针；不足以批准混合架构正式替换 v1.5 基线  
> 日期：2026-10-07

## 1. 可以被证据支持的结论

CR-001 已经从“概念建议”变为“具备安全边界、验收器、测试和可部署包的实验路线”。本地结果证明：若 ADP 能安全携带角色凭据并产生可导出的真实工具轨迹，Python 侧已经能够限制取证范围、区分 Rider/Driver、记录每次工具返回，并拒绝“只猜中真实 ID、但本次没有取到该证据”的伪自主取证。

这降低了混合路线的工程和安全不确定性，支持继续投入一次严格限时的云端 Gate A 探针。

本地结果不能证明 ADP 已经完成自主取证，也不能证明混合架构已经优于原路线。正式路线变更仍必须等待真实跨系统闭环。

## 2. 原路线尚未解决的问题

原 v1.5 路线由本地 Python 负责模型接入、Agent 循环、工具回传、调用预算、日志和最终门禁。其控制力强，但当前仍缺少已经跑通的模型 API 通道和真实 Agent 工具调用循环。

继续原路线还需要：

1. 验证模型 API、鉴权和兼容性；
2. 自行实现 Rider、Driver、Judge 的完整调用循环；
3. 自行实现工具选择、工具结果回传和结构修复；
4. 自行构建可展示的三 Agent 调用轨迹；
5. 再执行 Gate A。

ADP 路线已经真实运行过三个角色，因此其主要未知项集中为“能否安全、自主、可验证地调用工具”。这就是继续探针具有现实价值的根本原因。

## 3. 已经完成的可验证工程结果

### 3.1 运行级范围不再由模型决定

已实现短期运行清单，Python 在运行前固定：

- `run_id`；
- `case_id + case_version`；
- `policy_version`；
- 过期时间；
- 每个角色的请求次数上限；
- Rider、Driver、Judge 三个不同的随机运行令牌。

工具请求体不再接受 `case_id`、`case_version` 或 `policy_version`。模型无法通过修改参数切换案件或政策。原始令牌不写入运行清单，服务端只保存 SHA-256 哈希和非敏感 token ID。

### 3.2 角色独立性可以由服务端证明

Rider、Driver、Judge 使用不同令牌。服务端通过令牌识别角色，而不是相信模型自己填写的角色名称。

审计记录包含：

- `run_id`；
- 角色；
- 请求 ID；
- 接口；
- 服务端绑定的案件、版本和政策；
- 参数摘要；
- 返回给该角色的 evidence/rule ID；
- 开始时间、结束时间和耗时；
- 请求序号、状态和错误码；
- 服务实例 ID。

审计只保存经过允许的计数和枚举摘要，不保存请求体的字段值。验证失败响应也只返回错误数量和错误类型，不回显 Pydantic 输入。新增负向测试把同一个假密钥同时作为非法 JSON 字段名和值提交，并确认 HTTP 响应、JSONL 文件和 stdout 三处均不包含该值。

客户端提交的 `X-Request-Id` 不再被信任或回显。服务端为每个请求生成 `rr-` 加 32 位小写十六进制字符的请求 ID，并以响应头返回供 ADP 轨迹关联。新增负向测试把假密钥放入 `X-Request-Id`，并确认 HTTP 响应、JSONL 文件和 stdout 三处均不包含该值。

因此，Rider 和 Driver 是否分别调用证据工具，可以由 Python 审计验证，而不是依赖 Agent 的文字自述。

### 3.3 已堵住“看见 ID 就伪装取证”的漏洞

`get_case_snapshot` 不再返回 `evidence_refs`，只返回证据类型和数量。模型只有实际调用 `get_trip_evidence` 才能取得 evidence ID。

探针验收器进一步要求：

- Rider 和 Driver 都必须有各自成功的证据工具请求；
- 最终引用必须非空；
- 每个引用必须属于该角色、该 `run_id` 本次工具返回的 ID 集合；
- 引用了其他角色得到的 ID、其他运行的 ID，或者真实但本次未返回的 ID，均判失败。

对应负向测试已经证明：即使引用的是数据集中真实存在的 evidence ID，只要该 ID 没有返回给这个角色，本次 Gate A 仍会失败。

### 3.4 已建立跨系统验收契约

本地验收器要求同一个 `run_id` 出现在：

- ADP 导出的模型调用轨迹；
- Rider 最终论证；
- Driver 最终论证；
- Judge End 单层 JSON；
- Python 确定性门禁结果；
- 每次工具审计。

同时分别检查：

- ADP 导出的模型调用数为 3–7 次；
- Rider、Driver、Judge 三个角色均真实出现；
- 从 ADP 工作流开始到 Python 门禁结束的端到端耗时不超过 120 秒；
- End 输出是一个 JSON 对象，而不是转义后的 JSON 字符串；
- Judge 引用属于当前快照和政策；
- Judge 建议与 Python 确定性政策求值一致；
- 一次探针只观察到一个工具服务实例。

ADP 与 Python 不再只依赖共享 `run_id` 做宽松关联。验收器要求逐请求匹配双方记录中的 request ID、角色、operation、返回 evidence/rule ID 和时间窗口；任一请求在另一侧缺失或内容不一致即失败。

Raw End 输出从原始文件直接解析。若顶层是包含 JSON 的字符串而不是 JSON 对象，会在进入 Pydantic 之前失败。

ADP 导出文件必须原样保存并计算 SHA-256，再由人工把文件哈希与平台 trace ID、request ID 和控制台导出来源核对。代码明确记录：文件哈希只能证明被审查文件此后未变化，不能充当腾讯云的密码学签名；`source="ADP_EXPORTED_TRACE"` 本身不再被视为来源证明。

工具 HTTP 次数不会被误当成模型调用次数。没有 ADP 模型调用证据即判“未证明通过”。

## 4. 自动化验证结果

当前完整测试结果：**42 项通过，0 失败**。

| 测试组 | 数量 | 覆盖重点 |
|---|---:|---|
| Gate B / Delta | 17 | 两类纠纷、证据完整性、政策、金额、冲突和 Delta |
| 运行清单与工具 API | 17 | 令牌哈希、过期、超限、范围、角色审计、固定 HTTPS、请求值和外部请求 ID 不落日志 |
| Gate A 探针验收器 | 6 | 完整证据、未返回 ID、调用预算、逐请求匹配、Raw End、端到端期限 |
| 容器启动保护 | 2 | 单实例确认缺失时拒绝启动、确认值不绕过运行清单校验 |

已验证的关键负向行为：

- 无令牌请求返回 401；
- 过期令牌被拒绝；
- 超过角色请求上限返回 429；
- 请求体尝试切换到其他案件返回 422；
- HTTP OpenAPI 地址被构建器拒绝；
- 原始令牌不会出现在运行清单或工具审计中；
- 非法请求中的假密钥值不会出现在 HTTP 响应、JSONL 或 stdout；
- `X-Request-Id` 中的假密钥不会被回显或写入日志；
- 未确认 CloudBase Run 最小/最大实例数均为 1 时，容器拒绝启动；
- Rider 与 Driver 的证据调用可分别审计；
- 引用真实但未返回给该角色的 ID，探针失败；
- 超过 7 次模型调用，探针失败。
- ADP/Python request ID 不对应，探针失败；
- End 节点输出双重编码 JSON 字符串，解析失败；
- Python 门禁结束后总耗时超过 120 秒，探针失败。

## 5. 相比原路线现在能获得的优势

| 维度 | 原本地 Python 路线 | CR-001 混合探针路线 |
|---|---|---|
| 模型与三角色 | 模型通道和 Agent 循环尚未验证 | ADP 已有一次三角色真实顺序运行 |
| 自主取证 | 需要从头实现模型—工具循环 | 本地只读工具与角色审计已完成，待 ADP 真调用 |
| 可观察性 | 需要自行开发完整轨迹视图 | ADP 已提供节点、耗时、输入输出和 Token 视图 |
| 安全核心 | Python 控制 | 仍由 Python 控制，没有迁移给 ADP |
| 最终裁决 | Python 门禁 | 仍由 Python 门禁 |
| 比赛展示 | 需要额外证明三个 Agent 参与 | ADP 轨迹可作为平台侧证据，Streamlit 展示产品结果 |
| 最大未知项 | 模型接入和完整 Agent 循环 | 安全凭据传递、独立工具轨迹和日志导出 |

CR-001 的真正优势不是“云端更先进”，而是把尚未验证的范围从“模型接入 + Agent 循环 + 工具回传 + 轨迹 UI”缩小为一次明确、可失败、可止损的跨系统探针，同时保留 Python 的确定性安全核心。

- 尚未取得真实工具回传和角色级引用闭环；

- 尚未取得稳定 End 单层 JSON；

因此不能对外表述“混合架构已经成功”“Gate A 已通过”或“项目已经完成云端自主取证”。

## 7. 当前最合理的决策

现有结果足以支持以下决定：

> 继续执行已批准的、最多三小时的受控云端 Gate A 探针。

但不足以支持：

> 立即用混合架构正式替换项目实施总方案 v1.5。

正式切换至少需要同一次真实运行同时证明：

1. 三个角色令牌安全传递且不进入模型可见数据或展示日志；
2. Rider 和 Driver 各自真实调用 `get_trip_evidence`；
3. 双方引用均来自各自本次实际收到的结果；
4. ADP 记录证明模型调用总数不超过 7；
5. 整案不超过 120 秒；
6. Judge End 节点稳定返回单层 JSON；
7. Python 确定性门禁接受结果。

任一项无法证明，应按止损条款停止，而不是降低验收标准。
